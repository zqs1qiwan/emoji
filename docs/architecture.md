# Architecture

This document gives contributors a map of how emoji-kit is assembled. For user-facing behavior, see the [API reference](api.md).

## Layers

1. **Pinned sources** — `data/sources/sources.json` lists upstream URLs, versions, sha256 hashes, and licenses. `data/sources/app-categories.json` holds curated overlays.
2. **Build scripts** — `scripts/**` fetch (development only), validate, normalize, and merge inputs into deterministic generated JSON under `data/generated`. `checksums.json` records a sha256 for each generated file.
3. **Core** — `src/index.ts` builds lookup indexes (by id, character, and hex code) once per kit, resolves strings and definitions, implements search/list/render, and exposes the default callable with bound helpers. `src/core.ts` re-exports it and adds the `createKit` alias. `src/types.ts` holds shared types.
4. **Data entry** — `src/data.ts` and `src/data-entry.ts` expose generated JSON as typed `emojis`, `aliases`, `apps`, `assets`, and `metadata` for `emoji-kit/data` and `emoji-kit/apps`.
5. **Adapters** — `src/react.ts` wraps the core for React consumers (`useEmojiKit`, `emojiProps`). `scripts/cli-template.mjs` is the plain-ESM CLI entry built to `dist/cli.js` and exposed as the `emoji-kit` binary.
6. **Outputs** — `dist/**` holds built JavaScript (ESM and CJS), declarations, and copied checksums. It is generated by `npm run build` and never hand-edited.

## Resolution flow

- **String input:** normalized (trim, strip colons, lowercase, snake-case), then matched as hex/character or as alias → emoji id. Character lookups strip the variation selector.
- **Object input:** an `EmojiDefinition` resolves direct keys (`id`, `hexcode`, `char`, `name`) in order, consulting the app alias map before global aliases when `app` is set. Gender aliases are tried before plain names. A valid `tone` (1–5) selects a skin variant.
- **References:** `emoji.define()` stores a tagged definition; resolving it reuses the object path without capturing a stale record.
- **Assets:** remote URLs are only attached when `allowRemoteAssets` is true; otherwise `assetUrl` stays undefined. Native platform is the default.
- **Rendering:** `renderText()` uses a single regular expression for `:name:` and `:app/name:` tokens, normalizes them, looks up the id, and substitutes the Unicode character (or normalized shortcode). It emits a string, never markup.

## Data integrity and safety

- The core imports checked-in JSON only: no `fetch`, no filesystem access, no timers, and no dynamic code execution.
- Raw JSON is treated as untrusted; build scripts validate checksums and normalize keys.
- All remote URLs are HTTPS references, and no vendor artwork is bundled.
- `npm run check:public` scans public files for local paths, caches, logs, debug artifacts, and binary files.

## Development commands

```sh
npm run data:build   # regenerate data/generated from pinned inputs
npm run data:check   # verify checksums / invariants
npm test             # behavior tests against dist
npm run typecheck    # TypeScript check
npm run build        # sync generated data + build dist
npm run check        # typecheck + test + build
npm run check:public # public hygiene
```

CI runs on Node 20 and 22 with `npm ci`, `npm run check`, and `npm run check:public`. A manual `data-refresh` workflow can verify that regenerated data does not drift without a commit; it never auto-commits.
